# Phase 0 — Spike Results

โค้ด: [`spike/`](../spike) · แผน: [PLAN.md](../PLAN.md) §5 Phase 0 · งาน: [TASKS.md](../TASKS.md) P0-xx

## วิธีรัน

```bash
cd spike && swift build
B=$(swift build --show-bin-path)/KAISpike
```

ต้องให้สิทธิ์ **Camera** และ **Accessibility** แก่แอป terminal ที่ใช้รัน (System Settings → Privacy & Security)

| ทดสอบ | คำสั่ง |
| --- | --- |
| Filter (ไม่ใช้กล้อง) | `$B --selftest` |
| Latency / fps / CPU (ไม่ขยับ cursor) | `$B --dry-run --duration 20` |
| Jitter ตอนมือนิ่ง | `$B --dry-run --still-test --anchor mcp` |
| Click accuracy (เกณฑ์ Go / No-go) | `$B --click-test --anchor mcp` — 30 เป้า (24/44/64 pt) กด Esc เพื่อหยุด |
| ใช้งานจริง | `$B --anchor mcp --mode absolute` |
| เทียบ anchor | `--anchor tip`, `--anchor mcp`, `--anchor palm` |
| เทียบ mapping | `--mode absolute`, `--mode relative` |

Pinch = จีบนิ้วโป้ง+ชี้ (ratio ของระยะนิ้วต่อขนาดมือ < 0.30 กด, > 0.45 ปล่อย) ปรับได้ใน `Config.swift`

## ผลที่ยืนยันแล้ว

- One Euro Filter (`--selftest`, minCutoff 1.0, beta 0.05, 30 fps): noise ตอนนิ่ง RMS 1.67 → 0.56 px, lag ตอนกวาด 600 px/s = 0.7 px
- ยังไม่ได้วัดด้วยกล้องจริง: process ที่ใช้พัฒนาไม่มีสิทธิ์ Camera

### ข้อสรุปชั่วคราว

- **Detection ไม่ใช่ปัญหา** เมื่อมืออยู่ในภาพเต็มมือ ตรวจเจอ 88–99% ของเฟรม เกณฑ์ confidence 0.3 ใช้ได้ (เฟรมที่ตกส่วนใหญ่คือ Vision ไม่เห็นมือ ไม่ใช่ joint confidence ต่ำ)
- **Filter ลด noise ความถี่สูงได้ ~38%** (step ระหว่างเฟรม 4.45 → 2.75 px) แต่ **ลดการแกว่งช้า ๆ ของมือไม่ได้** (σ แทบเท่าเดิม ~20/12 px) การแกว่งนี้มาจากมือที่ลอยในอากาศจริง ไม่ใช่ tracker
- **ผลต่อความแม่น:** σ ~20 px เกินรัศมีของเป้า 24 pt (12 pt) จึงคาดว่าเป้าเล็กจะคลิกยาก ต้องยืนยันด้วย `--click-test` (ยังไม่ได้รัน)
- **Latency p50 64–76 ms, p95 76–83 ms** เกือบคงที่และส่วนใหญ่น่าจะเป็นดีเลย์ของกล้อง (Vision ใช้ ~10 ms) งบ p95 < 80 ms ใน PLAN.md แทบไม่เหลือที่ให้ส่วนอื่นของ pipeline ควรพิจารณาปรับเกณฑ์หรือทำนายตำแหน่งชดเชย
- **CPU 21–25% ของ 1 core** (release) สูงกว่าเกณฑ์ 15% ต้องลดความละเอียด/เฟรมเรต หรือประมวลผลเฉพาะตอน engaged
- **fps 17–29** ผันผวน ยังไม่ได้ทดสอบเรื่องแสง
- **Pinch ผิดพลาด:** ในรอบ still-test ที่มือควรนิ่ง นับ pinch 1 ครั้งใน 2 จาก 4 รอบที่มีมืออยู่ในภาพ (รอบ 5 = 0)
- **Click test (รอบ 1, mcp + absolute, release, 53 วินาที, 30 เป้า):**

  | ขนาดเป้า | Hit | ระยะคลาดเฉลี่ย | เวลาเฉลี่ยต่อเป้า |
  | --- | --- | --- | --- |
  | 24 pt | 2/10 (20%) | 226 px | 1.9 s |
  | 44 pt | 3/10 (30%) | 189 px | 1.9 s |
  | 64 pt | 2/10 (20%) | 453 px | 1.5 s |

  **ไม่ผ่านเกณฑ์** (ต้อง ≥ 90% ที่ 44 pt) และระยะคลาด 190–450 px ใหญ่เกิน jitter (σ ~20 px) มาก บ่งว่ามีความคลาดเคลื่อนแบบเป็นระบบ (lag, offset ตอน pinch, หรือการแมป) ยังไม่ควรสรุป No-go จนกว่าจะแยกสาเหตุ latency ในรอบนี้ p50 81 ms / p95 91 ms
- **Click test รอบ 2** (เพิ่มสถิติ bias): hit 10% / 20% / 40% (24 / 44 / 64 pt), bias ≈ 0 (dx −19, dy −1 px) แต่ scatter สูง (σ 316 / 223 px), median error 151 px แบ่งเป็น 2 กลุ่มชัด ประมาณ 11 จาก 30 ครั้งคลาดไม่เกิน ~25 px (รวมเป้า 24 pt) ที่เหลือคลาด 100–800 px → ไม่ใช่ offset เป็นระบบ แต่คลิกบางครั้งเกิดผิดจังหวะ
- **Click test รอบ 3 (debounce pinch 2 เฟรม): ใช้ไม่ได้** ครบ 30 คลิกใน 10.6 วินาที (0.2 s/เป้า) = คลิกรัว สาเหตุที่พบ: ตอนจีบ ปลายโป้ง/ชี้ทับกัน confidence ต่ำ เฟรมถูกทิ้งเหมือนมือหาย → ปล่อยเมาส์ → เฟรมถัดไปที่ยังจีบอยู่นับเป็น pinch ใหม่ แก้แล้ว: ปลายนิ้วใช้เกณฑ์ confidence 0.1 และต้องปล่อยนิ้วจริงก่อนคลิกใหม่ (re-arm)
- **Click test รอบ 4 (หลังแก้ re-trigger + ปลายนิ้ว confidence 0.1 + debounce 2 เฟรม + re-arm): ผลหลัก**

  | ขนาดเป้า | Hit | ระยะคลาดเฉลี่ย | เวลาเฉลี่ยต่อเป้า |
  | --- | --- | --- | --- |
  | 24 pt | 10/10 (100%) | 5.3 px | 3.9 s |
  | 44 pt | 9/10 (90%) | 12.5 px | 2.7 s |
  | 64 pt | 8/10 (80%) | 53.8 px | 3.5 s |
  | รวม | 27/30 (90%) | median 10 px | |

  bias ≈ 0 (dx −7, dy −9 px) fps 29.8, hand detected 97%, latency p50 74.5 / p95 90.0 ms, CPU 24.5%
  - เมื่อคลิกตอน cursor นิ่ง แม่นมาก: เป้า 24 pt โดนทุกครั้ง คลาด ≤ 10 px
  - 3 พลาดจาก 30: 1 ครั้งคลาด ~390 px ขณะ cursor เคลื่อนที่ 1,007 px/s (pinch ผิดจังหวะระหว่างเคลื่อนมือ), 2 ครั้งคลาดเล็กน้อย (51 px กับเป้า 64 pt, 24 px กับเป้า 44 pt)
  - n = 10 ต่อขนาดเป้า ช่วงความเชื่อมั่นกว้าง ค่า 90% ที่ 44 pt อยู่ที่ขอบเกณฑ์พอดี ไม่ใช่ผ่านอย่างสบาย
  - เวลา 2.7–3.9 s ต่อเป้า ช้ากว่าเมาส์มาก (ส่วนหนึ่งเพราะผู้ทดสอบเล็งระวัง และมี freeze 150 ms)
- **เทียบ anchor** (absolute, release, เพิ่มเกณฑ์ความเร็วคลิก 400 px/s, 30 เป้าต่อ anchor, n = 10 ต่อขนาด):

  | Anchor | 24 pt | 44 pt | 64 pt | รวม | median error | หมายเหตุ |
  | --- | --- | --- | --- | --- | --- | --- |
  | **mcp** (รอบ 4, ก่อนมี speed gate) | 10/10 | 9/10 | 8/10 | 27/30 | 10 px | bias ≈ 0 |
  | **palm** | 7/10 | 9/10 | 10/10 | 26/30 | 12 px | มือหลุดเฟรมบ่อย (detect 85%), scatter dx 108 px |
  | **tip** | 1/10 | 3/10 | 5/10 | 9/30 | 32 px | คลาดลงทางเดียว (dy +10 เฉลี่ย, หลายครั้ง +20…+70) ปลายนิ้วขยับลงตอนจีบ |

  mcp กับ palm ต่างกันอยู่ในช่วงสัญญาณรบกวนของตัวอย่าง (palm 26/30 vs mcp 27/30) mcp ชนะที่เป้าเล็ก tip แย่ชัดเจนและคลาดเป็นระบบ
  รอบ mcp ใหม่หลังเพิ่ม speed gate ยังไม่ได้รัน
- **Relative mode: ยังไม่ได้ผล** รัน 2 ครั้งแต่กล้องไม่เห็นมือเลย (0%) และหน้าต่างปิดที่ 12.7 s / 3.5 s ไม่นับเป็นข้อมูล
- **ยังไม่ได้ทดสอบ:** relative mode, anchor tip/palm → **ยังไม่ตัดสิน Go / No-go**

### บั๊กที่พบและแก้ระหว่างสไปค์

- ตัวกรอง One Euro ทำงานกับค่า normalized 0–1 แต่ `beta` ตั้งไว้สำหรับหน่วยพิกเซล filter จึงไม่ปรับตามความเร็ว แก้โดยกรองในหน่วย milli-frame (×1000) selftest เดิมใช้พิกเซลจึงไม่เจอ
- Still-test เริ่มนับ 3 วินาทีทันทีหลัง build จนผู้ใช้ไม่ทัน เพิ่มเป็น 6 วินาที
- เพิ่ม `--min-conf` และสรุปเหตุผลที่เฟรมถูกทิ้ง

## การตัดสินใจ (กรอกหลังวัด)

- Tracking provider: **Apple Vision** (ตรวจเจอ 97%, ใช้เวลา ~13 ms ต่อเฟรม) ข้าม MediaPipe ไว้ก่อน ยกเว้นผลแสงน้อย/ระยะไกลแย่
- Mapping mode: **absolute** (relative ยังไม่ได้ทดสอบ)
- Anchor point: **mcp** (โคนนิ้วชี้) — เทียบแล้ว: mcp 27/30, palm 26/30, tip 9/30 (tip คลาดลงเป็นระบบ)
- Filter เริ่มต้น: minCutoff 1.0 · beta 0.05 (หน่วย milli-frame ×1000)
- Pinch: debounce 2 เฟรม, ปลายนิ้ว confidence 0.1, ต้องปล่อยนิ้วก่อนคลิกใหม่
- **Go / No-go: Go แบบมีเงื่อนไข** — ที่ 44 pt แม่น 90% (9/10) ตรงเกณฑ์พอดีและตัวอย่างน้อย; เป้า 24 pt แม่น 10/10 เมื่อ cursor นิ่ง ความเสี่ยงที่ยังเปิดอยู่:
  1. คลิกผิดจังหวะตอนมือเคลื่อนเร็ว → เพิ่ม speed gate แล้ว (`--max-click-speed`, default 400 px/s) แต่ยังไม่ได้วัดซ้ำกับ mcp
  2. Latency p95 ~90 ms เกินงบ 80 ms (ดีเลย์ส่วนใหญ่มาจากกล้อง)
  3. CPU ~25% เกินเกณฑ์ 15%
  4. ยังไม่ได้ทดสอบแสงน้อย/ระยะต่าง ๆ, กล้องภายนอก, ใช้งานต่อเนื่อง (แขนล้า), false click ระหว่างทำงานปกติ
